# Veilbox — Project Context

## Goal
Build Veilbox, a Metasploitable-style OS (custom Linux kernel with embedded initramfs + state disk) that boots to a login prompt then a full BusyBox shell, with services running in the background. The OS boots from a disk image, compatible with any VM (VirtualBox, QEMU) or bare metal.

## System Info
- Host: Fedora 44, GCC 16.1.1, binutils 2.46
- QEMU: 10.2.2 (SeaBIOS 1.17.0)
- Kernel: 7.1.0-rc6
- Build: `make defconfig` + `kernel/configs/custom-os.config` + embedded initramfs

## Key Files
- `build.sh`: Main build script (configure kernel, build rootfs, create bootable disk + VDI)
- `test.sh`: QEMU test runner (direct kernel boot, state disk via raw image)
- `kernel/configs/custom-os.config`: Kernel config fragment
- `rootfs/etc/inittab`: Spawns getty login on tty1 and ttyS0
- `rootfs/etc/init.d/rcS`: Init script (mounts proc/sys/dev, DHCP, start containerd + dropbear)
- `rootfs/etc/passwd`: Root user entry
- `rootfs/etc/shadow`: Hashed root password (veiladmin)
- `rootfs/etc/dropbear/authorized_keys`: SSH public key for root
- `rootfs/root/.profile`: Colored shell prompt with IP display

## Build Artifacts (`output/`)
- `veilbox.raw`: 8GB raw disk image (GRUB + kernel with embedded initramfs, state partition)
- `veilbox.vdi`: VirtualBox disk image (converted from raw)
- `vmlinuz`: bzImage kernel (with embedded initramfs)
- `state.img`: 128MB ext4 state disk (legacy)
- `rootfs.squashfs`: XZ-compressed rootfs (for reference)
- `ssh-test-key`: ED25519 SSH private key for root access

## Build / Test
```
./build.sh            # Full build (≈5 min, kernel rebuild takes most time)
./build.sh --clean    # Clean rebuild
./test.sh             # Boot in QEMU (direct kernel, MEM=2G for large initramfs)
./test.sh --bios      # Boot via SeaBIOS/GRUB (full BIOS boot path)
./test.sh --check     # Auto health check (exit 0 if login prompt detected)
MEM=2G ./test.sh      # 2GB RAM (required, initramfs ~90MB)
```

## Important Fixes
1. **boot failure**: `make tinyconfig` triple-faults under QEMU 10.2.2. Fixed by using `make defconfig` as base.
2. **OOM**: Initramfs ~90MB, need MEM=2G instead of default 512M.
3. **Kernel header**: `CONFIG_EFI_STUB=y` for valid MZ/PE boot header.
4. **Serial console**: `CONFIG_TTY=y`, `CONFIG_ACPI=y` for serial8250.
5. **SSH timeout**: Dropbear v2025.89 `-w` means **Disallow** root logins (opposite of older versions); also missing `udhcpc/default.script` prevented DHCP.
6. **SSH permission denied**: `build_ssh_keys()` generates ED25519 key pair and `authorized_keys`.
7. **GRUB boot**: Switched from QEMU `-kernel` to disk-based GRUB boot, then back to direct kernel boot, then finally made GRUB work. See "GRUB Rootless Install" below.

## Boot Methods
Two boot methods are available:
1. **Direct kernel boot** (`test.sh` default): QEMU `-kernel output/vmlinuz` with embedded initramfs. Fast for dev.
2. **GRUB BIOS boot** (`test.sh --bios`): Full SeaBIOS → GRUB → kernel path. Use for VirtualBox/bare-metal validation.

## GRUB Rootless Install
The rootless GRUB installer in `build.sh:create_bootable_disk()` step 5 uses a Python script that:

1. **Saves partition table**: Reads 64 bytes at 0x1BE-0x1FD from `boot.img` (non-empty, contains boot code data). After writing `boot.img` to LBA 0 (which overwrites this region), restores the partition table from sfdisk.

2. **Writes boot.img** to LBA 0 (preserving partition table at 0x1BE)

3. **Writes core.img** starting at LBA 1 (generated fresh by `grub2-mkimage`, blocklist is correct — do NOT patch it)

4. **Embedded config** (`-c embedded.cfg`): `search --label --set=root VEILBOX` + `set prefix=($root)/boot/grub`. This auto-finds the root partition by label.

### Why blockslist patching is wrong
GRUB 2.x blocklist format is 12 bytes, not `{start(4), len(4), seg(4)}`:
- Offset 0x1F4: `start` (4 bytes) — first LBA
- Offset 0x1F8: `start_hi` (4 bytes) — must be zero
- Offset 0x1FC: `remaining` (2 bytes) — number of sectors remaining
- Offset 0x1FE: `seg` (2 bytes) — segment to load at

`grub2-mkimage` already outputs the correct blocklist `{start=2, start_hi=0, remaining=338, seg=0x0820}`. Patching it overwrites `start_hi` with sector count, corrupting the format and triggering the geometry error at `diskboot.img:0x63`.
