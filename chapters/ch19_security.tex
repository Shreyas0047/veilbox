\chapter{Security Hardening}
\label{ch:security}

Security is a primary design goal for Veilbox. The system is hardened at
every layer: kernel configuration reduces the attack surface, BusyBox
eliminates setuid binaries, Dropbear provides encrypted access, and
container runtimes use Linux security primitives.

\section{Kernel Security Features}

\subsection{Minimal Attack Surface}

The kernel is configured without unnecessary subsystems:
\begin{itemize}[nosep]
  \item No sound subsystem (CONFIG\_SOUND=n).
  \item No USB stack (CONFIG\_USB=n).
  \item No Wi-Fi or Bluetooth (CONFIG\_WLAN=n, CONFIG\_BT=n).
  \item No ATA or SCSI drivers (CONFIG\_ATA=n, CONFIG\_SCSI=n).
  \item No filesystems beyond ext4, proc, sysfs, tmpfs, devtmpfs,
        overlay, squashfs.
  \item No PCMCIA, FireWire, InfiniBand, or ISDN.
\end{itemize}

\subsection{Kernel Hardening}

The kernel is hardened with compile-time protections and attack surface reduction:

\begin{lstlisting}
CONFIG_FORTIFY_SOURCE=y        # Buffer overflow detection
CONFIG_SECURITY_YAMA=y         # Ptrace scope restrictions
CONFIG_DEVMEM=n                # Disable /dev/mem access
CONFIG_KEXEC=n                 # Disable kernel exec
CONFIG_HIBERNATION=n           # Disable suspend-to-disk
CONFIG_PROC_KCORE=n            # Disable /proc/kcore
CONFIG_DEBUG_FS_ALLOW_NONE=y   # Block debugfs mounts at runtime
\end{lstlisting}

ASLR entropy is increased at boot via sysctl:
\begin{lstlisting}
echo 32 > /proc/sys/vm/mmap_rnd_bits
\end{lstlisting}

Additional runtime kernel hardening is applied at boot:
\begin{lstlisting}
sysctl -w kernel.kptr_restrict=2        # Hide kernel pointers
sysctl -w kernel.dmesg_restrict=1      # Restrict dmesg to root
sysctl -w net.ipv4.conf.all.rp_filter=1 # Reverse path filtering
sysctl -w net.ipv4.conf.all.accept_source_route=0 # Disable source routing
sysctl -w net.ipv4.tcp_syncookies=1    # SYN flood protection
\end{lstlisting}

\subsection{Mandatory Security Options}

\begin{lstlisting}
CONFIG_SECCOMP=y           # Syscall filtering
CONFIG_SECCOMP_FILTER=y    # BPF-based filters
CONFIG_SECURITY=y          # Security framework
CONFIG_SECURITY_APPARMOR=y # AppArmor LSM
CONFIG_SECURITY_YAMA=y     # Ptrace scope restrictions
CONFIG_DEFAULT_SECURITY_YAMA=y
CONFIG_SECURITY_NETWORK=y  # Network security hooks
\end{lstlisting}

\subsection{CGroup Device Control}

CGroup device controllers restrict container access to host devices:

\begin{lstlisting}
CONFIG_CGROUP_DEVICE=y
\end{lstlisting}

\section{Userspace Security}

\subsection{No Setuid Binaries}

The Veilbox root filesystem contains no setuid binaries. BusyBox can be
configured with setuid support disabled:

\begin{lstlisting}[language=bash]
# BusyBox config: disable setuid
# CONFIG_FEATURE_SUID is not set
\end{lstlisting}

\subsection{No Package Manager}

Without a package manager, there is no mechanism for an attacker to
install software, exploit repository vulnerabilities, or run
post-install scripts.

\subsection{No Compilers}

No compilers or interpreters (other than busybox ash) are present in the
root filesystem. An attacker who gains shell access cannot compile
exploit code.

\subsection{Read-Only Root}

The root filesystem is embedded in the kernel binary. Runtime modification
of system binaries is impossible — changes are lost on reboot.

\subsection{Minimal Services}

Only two network services run: Dropbear (SSH) and containerd (local Unix
socket only). No HTTP, FTP, SMTP, NFS, SMB, or any other services.

\section{SSH Hardening}

\begin{itemize}[nosep]
  \item \textbf{ED25519 keys}: Modern, fast, secure host keys.
  \item \textbf{PBKDF2 password hash}: /etc/shadow uses SHA-512 rounds.
  \item \textbf{Port forwarding}: QEMU limits SSH to port forwarding
        only (no public guest IP by default).
  \item \textbf{Key-based auth}: Optional but supported with auto-generated
        ED25519 key pair.
\end{itemize}

\section{Container Security Primitives}

\subsection{Namespace Isolation}

Each container runs in isolated namespaces:
\begin{itemize}[nosep]
  \item \textbf{PID}: Container processes cannot see host processes.
  \item \textbf{Network}: Container has its own network stack.
  \item \textbf{Mount}: Container has its own filesystem hierarchy.
  \item \textbf{UTS}: Container has its own hostname.
  \item \textbf{IPC}: Container has its own IPC resources.
  \item \textbf{User}: (Optional) Container root can be mapped to an
        unprivileged host user.
\end{itemize}

\subsection{Seccomp}

Seccomp-BPF filters restrict the system calls available to container
processes. The default Docker/containerd seccomp profile allows
approximately 300 of the 400+ Linux syscalls, blocking dangerous ones
like \texttt{module\_init}, \texttt{kexec\_load}, and \texttt{ptrace}.

\subsection{Capability Dropping}

Linux capabilities are dropped from container processes:
\begin{lstlisting}
CAP_SYS_ADMIN     # Mount, namespace operations
CAP_NET_ADMIN     # Network configuration
CAP_SYS_MODULE    # Kernel module loading
CAP_SYS_RAWIO     # I/O port access
CAP_SYS_PTRACE    # Process tracing
\end{lstlisting}


\section{Container Security Architecture}

\subsection{Defense in Depth}

Veilbox implements multiple layers of container security:

\begin{enumerate}[nosep]
  \item \textbf{Namespaces}: Each container has isolated views of the
        system (processes, network, mounts, etc.).
  \item \textbf{Cgroups}: Resource limits prevent denial-of-service
        from a single container.
  \item \textbf{Seccomp-BPF}: System call filtering blocks dangerous
        syscalls.
  \item \textbf{Capability dropping}: Removes privileges like
        CAP\_SYS\_ADMIN and CAP\_NET\_ADMIN.
  \item \textbf{Read-only rootfs}: Containers can be started with
        read-only root filesystems.
  \item \textbf{No new privileges}: The NO\_NEW\_PRIVS flag prevents
        privilege escalation via setuid binaries.
\end{enumerate}

\subsection{Seccomp Default Profile}

The default seccomp profile blocks approximately 60 system calls that
are dangerous or unnecessary for containers:

\begin{lstlisting}
# Blocked syscalls (partial list)
kexec_load        # Loading a different kernel
open_by_handle_at # Bypass mount namespace
init_module       # Loading kernel modules
finit_module      # Loading kernel modules
delete_module     # Unloading kernel modules
ptrace            # Process tracing and debugging
swapon            # Enabling swap
swapoff           # Disabling swap
sethostname       # Changing hostname
setdomainname     # Changing domain name
\end{lstlisting}

\subsection{SELinux Considerations}

Veilbox does not use SELinux (it adds complexity and binary size). For
systems requiring SELinux:

\begin{lstlisting}
CONFIG_SECURITY_SELINUX=y
CONFIG_DEFAULT_SECURITY_SELINUX=y
\end{lstlisting}

However, this requires SELinux policies and tools which add approximately
10 MB to the initramfs.

\section{Audit Trail}

The system log captures security-relevant events:

\begin{lstlisting}
# Monitor authentication attempts
grep "dropbear" /var/log/messages

# Monitor container starts/stops
grep "containerd" /var/log/messages

# Monitor failed login attempts
grep "Failed" /var/log/messages
\end{lstlisting}

\section{Bridge Networking}

CNI bridge networking provides network isolation for containers.
The default configuration creates a virtual bridge \texttt{cni0} on
\texttt{10.88.0.0/16} and uses iptables NAT for external access:

\begin{lstlisting}[language=bash]
# Inside the VM
nerdctl run -d --name web nginx:alpine   # IP on 10.88.0.0/16
nerdctl run -d --name app -p 8080:80 nginx:alpine  # Port-mapped
\end{lstlisting}

The \texttt{bridge} plugin creates the veth pair, \texttt{portmap}
forwards host ports, and \texttt{firewall} isolates traffic.

\subsection{Firewall Rules}

A MASQUERADE rule is applied at boot to enable container outbound
connectivity:

\begin{lstlisting}
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
\end{lstlisting}

\section{eBPF Tracing}

The \texttt{bpftool} utility is built from the kernel tree and installed
at \texttt{/usr/bin/bpftool}. A minimal execve tracer
(\texttt{trace-exec.sh}) logs process executions to syslog:

\begin{lstlisting}[language=bash]
# Start tracer
trace-exec.sh start

# View exec events
grep "bpf-exec" /var/log/messages
\end{lstlisting}

\section{Health Endpoint}

A Unix socket HTTP health endpoint runs at \texttt{/var/run/health.sock}.
It returns JSON status on connect:

\begin{lstlisting}[language=bash]
# Query health
echo "GET /" | nc -U /var/run/health.sock

# Response:
{"status":"ok","uptime":42}
\end{lstlisting}

The endpoint is used for system monitoring and orchestration health
checks.

\section{Registry Mirror}

containerd is configured with a registry mirror for docker.io to improve
pull reliability and speed:

\begin{lstlisting}
[plugins."io.containerd.grpc.v1.cri".registry.mirrors."docker.io"]
  endpoint = ["https://docker.io", "https://mirror.gcr.io"]
\end{lstlisting}

This also reduces pressure on Docker Hub rate limits.

\section{AppArmor}

AppArmor is a Mandatory Access Control (MAC) system implemented as a
Linux Security Module (LSM). It confines programs by loading profiles
that specify what files, capabilities, and network operations a process
may access.

\subsection{Kernel Configuration}

\begin{lstlisting}
CONFIG_SECURITY_APPARMOR=y
CONFIG_SECURITY_APPARMOR_BOOTPARAM_VALUE=1
\end{lstlisting}

\subsection{Default Container Profile}

Every container started with \texttt{nerdctl} runs under the
\texttt{docker-default} profile. The profile blocks access to sensitive
kernel filesystems and container escape vectors:

\begin{lstlisting}
profile docker-default flags=(attach_disconnected,mediate_deleted) {
  capability,
  network,
  mount,
  / r,
  /** rwm,
  /bin/** rix,
  /usr/** rix,
  /lib/** rix,
  deny /sys/[^f]*/** w,
  deny /sys/firmware/** w,
  deny /sys/kernel/security/** w,
  deny /proc/sysrq-trigger w,
  deny /proc/kcore r,
  deny /proc/kmsg r,
}
\end{lstlisting}

\subsection{Daemon Profiles}

In addition to the container profile, AppArmor confines system daemons:

\textbf{Dropbear (usr.sbin.dropbear)} -- restricts SSH daemon to key
files, log writes, and network access:

\begin{lstlisting}
profile usr.sbin.dropbear /usr/sbin/dropbear {
  capability net_bind_service,
  capability sys_tty_config,
  /etc/dropbear/** r,
  /root/.ssh/authorized_keys r,
  /var/log/messages w,
  network tcp,
}
\end{lstlisting}

\textbf{Containerd (usr.bin.containerd)} -- confines the container
runtime to state directories, cgroup access, and mount operations:

\begin{lstlisting}
profile usr.bin.containerd /usr/bin/containerd {
  capability,
  /mnt/state/** rw,
  /run/containerd/** rw,
  /sys/fs/cgroup/** rw,
  mount fstype=overlay,
  mount fstype=tmpfs,
  ptrace (read, trace),
  signal (send, receive) set=(kill, term),
}
\end{lstlisting}

\subsection{Building from Source}

Since Fedora does not ship \texttt{apparmor-utils}, \texttt{apparmor\_parser}
is built from source during \texttt{build.sh}. The build:

\begin{enumerate}[nosep]
  \item Downloads the AppArmor v3.0.13 tarball
  \item Generates \texttt{af\_protos.h} from kernel headers
  \item Compiles \texttt{libapparmor.a} manually (bypasses autotools)
  \item Builds \texttt{apparmor\_parser} linked against \texttt{libstdc++}
\end{enumerate}

\section{Kernel Lockdown}

The Lockdown LSM restricts userspace access to the running kernel.
When active, it prevents:

\begin{itemize}[nosep]
  \item Reading/writing kernel memory via \texttt{/dev/mem}
  \item Using \texttt{kexec} to load a different kernel
  \item Loading unsigned kernel modules (see Module Signing)
  \item Debugging the kernel via kdbus/kgdb
\end{itemize}

\begin{lstlisting}
CONFIG_SECURITY_LOCKDOWN_LSM=y
CONFIG_SECURITY_LOCKDOWN_LSM_EARLY=y
\end{lstlisting}

\section{Module Signing}

All kernel modules are signed during the build with an ephemeral
key. The kernel refuses to load unsigned modules:

\begin{lstlisting}
CONFIG_MODULE_SIG=y
CONFIG_MODULE_SIG_FORCE=y
CONFIG_MODULE_SIG_SHA512=y
# Key pair generated at build time
\end{lstlisting}

\section{Rootless Containers}

User namespace remapping allows container root to map to an
unprivileged host UID. The \texttt{/etc/subuid} and \texttt{/etc/subgid}
files grant 65536 subordinate IDs:

\begin{lstlisting}
# /etc/subuid
root:100000:65536

# /etc/subgid
root:100000:65536
\end{lstlisting}

Containers can be started with \texttt{--userns=host} for full root
privilege, or left at the default (no remapping) for current behavior.

\section{Audit Logging}

Kernel audit rules are loaded at boot to track security-relevant events:

\begin{lstlisting}
# /etc/audit/rules.d/container.rules
-w /usr/bin/nerdctl -p x -k container-manage
-a exit,always -F arch=b64 -S execve -k exec
-a exit,always -F arch=b64 -S clone -k process-create
-a exit,always -F arch=b64 -S fork -k process-create
-a exit,always -F arch=b64 -S mount -k mount
\end{lstlisting}

Events are sent to the kernel audit subsystem. Since \texttt{auditd}
is not present, logs are captured via \texttt{syslogd}:

\begin{lstlisting}[language=bash]
grep "audit" /var/log/messages
\end{lstlisting}

\section{Supply Chain Security}

\texttt{cosign} is installed at \texttt{/usr/bin/cosign} for
verifying container image signatures:

\begin{lstlisting}[language=bash]
# Verify with a public key
cosign verify --key cosign.pub <image>

# Keyless verification (transparency log)
cosign verify <image>
\end{lstlisting}

\section{Default Resource Limits}

The \texttt{nerdctl} binary is wrapped in a shell script that injects
default resource limits unless the user overrides them:

\begin{lstlisting}[language=bash]
# Wrapper at /usr/bin/nerdctl
# Actual binary at /usr/bin/nerdctl.real
\end{lstlisting}

Default values: \texttt{--cpus=1} and \texttt{--memory=512m}. Override
with explicit flags:

\begin{lstlisting}[language=bash]
nerdctl run --cpus=4 --memory=2g nginx:alpine
\end{lstlisting}

\section{Secure State Mount}

The persistent state partition is remounted at boot with security
options:

\begin{lstlisting}
mount -o remount,noexec,nodev,nosuid /mnt/state
\end{lstlisting}

This prevents execution of untrusted binaries from the persistent
volume, even if an attacker writes files to it.

\section{Network Security}

\subsection{Host Firewall Rules}

Iptables rules applied at boot for container isolation:

\begin{lstlisting}
# Default: drop incoming, allow outgoing
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# Allow loopback
iptables -A INPUT -i lo -j ACCEPT

# Allow established connections
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# Allow SSH
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow container traffic to external
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
\end{lstlisting}

CNI bridge plugin appends its own FORWARD rules for container traffic
(\texttt{-A FORWARD -i cni0 -j ACCEPT}).
